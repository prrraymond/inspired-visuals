# The End-to-End Flow — Build Notes

**Date:** 2026-09-17
**Scope built:** browse → pick → supply data → review parameters → render → caption, against the
three real templates. Local only. No accounts, no auth, no payment, no deploy.
**Verification:** every claim below was exercised over HTTP against the running app, driving the
same requests a browser makes.

**Headline:** the flow works on all three templates. What fought hardest was not the interaction
design — that survived almost intact — but the fact that **a template declares nothing about
itself**, so most of this build is machinery for recovering an interface that should have been
written down.

---

## What was built

| File | What it does |
|---|---|
| `Scripts/lib/input_check.py` | user data vs. contract, with specific findings and applicable repairs |
| `Scripts/lib/template_iface.py` | recovers a template's interface by parsing it; applies captions to a built figure |
| `Scripts/lib/render_guard.py` | `manual_proposal()` added — a person's values as their own proposal |
| `gallery/render_local.py` | the exec + render path. **Local-only, fenced in a banner** |
| `gallery/runs.py` | in-memory run store. Local-only |
| `gallery/app.py` | the flow routes |
| `gallery/templates/{use,data,parameters,output}.html` | the four screens |
| `gallery/static/strip.js` | the distribution strip, ported from the canvas |

Run with `python3 gallery/app.py`; **http://127.0.0.1:5111**.

### The exec fence

`render_local.py` opens with a banner block stating that it exec()s generated code with
user-supplied data, why that is acceptable here (binds to 127.0.0.1, no auth, single operator —
the same trust model the build-time pipeline runs under), and that **it must not survive into
anything deployed without sandboxing**, naming what a replacement needs: separate process, no
network, no filesystem, hard timeout. `EXEC_IS_LOCAL_ONLY = True` is a grep-able marker.
`runs.py` carries the same warning for its process-global store.

## What fought me

### 1. A template declares nothing about itself

This was the dominant cost. A template is a Python file with module-level
`<role>_column = "<default>"` assignments and some constants. There is no manifest, so
`template_iface.py` recovers the interface by parsing the AST, and recovers *optionality* by
looking for `x in df.columns` guards — because whether a column is required is expressed only
in how the code happens to use it.

It works on all three, and it is inference over source rather than a declaration:

```
CHT-6FBD47   state REQUIRED · value REQUIRED · category REQUIRED
             label optional · lat optional · lon optional · label_flag optional
CHT-85FB02   facet REQUIRED · x REQUIRED · y REQUIRED
CHT-678195   x REQUIRED · y REQUIRED
```

A `requires` block in the template — or in the contract — would delete this module.

### 2. The contract's columns are not the template's columns

`CHT-85FB02`'s contract records `year, state, value`. Its template reads `facet, x, y`. Nothing
maps between them. In the restore session I renamed the dataframe by hand and did not notice
that I was supplying a missing piece of the system.

The flow needs that mapping as a real step, so there is now a mapping screen. That turned out to
be the right answer rather than a workaround — the `*_column` indirection **is** the mapping
mechanism, so the screen uses the template as designed. But the contract should record which
column played which role, and does not.

### 3. The designed interaction survived; two details did not

The canvas interaction ported almost unchanged — drag or click the strip, live bin counts,
dashed ghost of the proposal, reasoning demoted to past tense rather than hidden, four states as
sentences. Two things broke on contact:

- **Axis labels clipped at the edges.** A centred first/last tick is half outside a clipped
  strip: `9.02` rendered as `02`, `23.45` as `23.`. The canvas domain never put a label hard
  against the edge. Edge ticks are now clamped instead of centred.
- **Bin bands too faint at real width.** The canvas was 1040 px wide with 10% tints; at the
  app's width they vanished. Raised to ~15%. The dots carry the encoding regardless.

The interaction itself needed no rethinking, which is the useful result: **the thing the canvas
was for — testing whether it felt like a form — held up.**

### 4. The caption applied twice

First render of `CHT-678195` carried its title twice: once from `TITLE_TEXT`, which the template
draws as an annotation, and once from a layout title the app added because `layout.title` was
empty. Both mechanisms are correct on their own. `apply_captions` now takes the set of roles
already satisfied by a constant and skips the fallback for those.

A second, smaller one: injecting a title into a template that never had one gave it nowhere to
go — it landed on the first subplot heading. Injecting a title now reserves top margin.

### 5. Unfilled captions blanked the placeholder

`Source / credit` disappeared when the user had not typed a source, while the form promised
"leave a field empty and the placeholder stays". An empty slot the reader can see is
information; a blank is indistinguishable from a chart that never had one. An unfilled caption
now leaves the placeholder standing.

### 6. `dict.values` shadowed a key in Jinja — again

`c.values` on a dict resolves to `dict.values`, not the key. **This is the same bug I hit
building the gallery a few days ago**, in a fresh dict, and the 500 looked identical. Renamed to
`points`, with the comment naming the precedent. A repeat of a known defect in new code is worth
recording as its own finding: the earlier fix was local, and nothing generalised it.

### 7. `GRID_STEP` has no owner

`CHT-85FB02` reads `BASELINE` (settled by a proposal) and `GRID_STEP` (not settled by anything).
Shipped at `100` for ratio data, it is nonsense against values of 12–18. The app computes a nice
step from the data spread and **logs it as an app default with no proposal behind it** rather
than passing it off as derived. It is a display parameter the contract has no concept of.

## The `year` problem, and what a `role` field would need

As instructed, **no heuristic was encoded.** Every non-null numeric column gets a proposal on
equal footing, so `CHT-85FB02` offers parameters for both `year` and `value` and the screen
treats them identically. **[VERIFIED — `parameters offered for: ['year', 'value']`]**

One thing did emerge from building it: **the flow already resolves the question elsewhere.** When
the user maps `y_column → value` on the mapping screen, they have stated which column is the
measure. `render_local` looks up the baseline from the proposal for the *mapped* y column, so the
right parameter drives the chart even though `year` also has one. The mapping is the user saying
what the data means — which is the division of labour the product is built on.

That suggests the shape of a `role` field, and what it must avoid.

### What it would need to look like

Per column in the contract, alongside `kind`:

```json
{"name": "year",  "kind": "numeric", "role": "time",     "role_by": "operator"}
{"name": "state", "kind": "categorical", "role": "dimension", "role_by": "operator"}
{"name": "value", "kind": "numeric", "role": "measure",  "role_by": "operator"}
```

| Requirement | Why |
|---|---|
| **Vocabulary: `measure`, `dimension`, `time`, `identifier`, `derived`** | Enough to answer "propose a parameter for this?" — only `measure` qualifies — without becoming a type system. `identifier` matters: a numeric ID must never be binned. `derived` marks a column the pipeline produced (the binned `category`), so it is never re-proposed. |
| **`role_by` provenance — `operator`, `sql`, `inferred`** | Same discipline as parameter proposals. A role nothing stands behind must not read as a fact. If it can only ever be `inferred`, it should not be in the contract. |
| **Nullable, and absence must be legible** | A contract derived before roles existed has none. Absent must mean "nobody has said", never "not a measure" — otherwise a backfill silently reclassifies 400 rows. |
| **Set where the knowledge is, not where the data is** | It cannot be derived. `year` is numeric, evenly spread, low-cardinality — and so is a count of children per household. The two are indistinguishable in the distribution. The natural sources are the **SQL** (the author knows `school_year_start` is time) or the **mapping step** (the user has already said which column is the measure). |
| **One role per column, per contract** | A column is the measure of *this* chart. Roles belong to the contract — the chart's view of the data — not to the underlying table. |

### What it must not do

- **Not a name heuristic.** `year`, `yr`, `fiscal_year` is a blocklist that fails on `year_over_year_growth`, which *is* a measure. The canvas mockup tagged the column "probably not a measure" and that tag was a guess wearing a fact's clothing.
- **Not inferred from cardinality or range.** 2013–2023 in steps of 1 describes a year and a small count equally well.
- **Not silently defaulted.** A column with no role should produce a proposal the user can dismiss — which is what happens today — rather than being quietly skipped.

**Cheapest first step, given the flow now exists:** have the mapping screen write the role back.
The user maps `y_column → value`; that is `role: measure, role_by: operator` at no extra cost in
attention, and it is the one moment in the flow where the person who knows is already being
asked.

## Still open

1. **Nothing is stored.** Renders live in memory and vanish with the run. `charts/<cid>/…png`
   and `Chart Image` remain empty; wiring the upload is a small, separate change.
2. **`exec()` is the blocker for anything beyond localhost** — the fence is a comment, not a
   sandbox.
3. **The contract records no role and no column→placeholder mapping** — items 2 and the `role`
   discussion above.
4. **`CHT-85FB02` still fails the caption gate** (`PROFIT`, `LOSS`, `RATIO`). The flow overrides
   them at render, so the chart is correct, but the stored template remains one the gate would
   reject. Regenerating it needs the updated Stage C prompt, which is untested.
